# Chladni — Real-Time Audio Physics Visualizer

A browser-based DSP pipeline that detects pitch from live microphone input and renders the corresponding Chladni standing-wave pattern in real time. No backend. No external audio libraries. Everything runs in the browser using Web Audio API primitives.

---

## What it does

Play a note or chord into your microphone. The pipeline detects the fundamental frequency (or frequencies), maps them to vibrational mode pairs `(m, n)` using the standing-wave equation for a square plate, and renders the nodal geometry as a sand pattern on a canvas.

Single notes produce green patterns. Chords superimpose multiple modes and render in purple — the interference between them approximates what happens on a real Chladni plate when driven at a complex frequency.

---

## Physics

A square plate vibrating at mode `(m, n)` has displacement:

```
Z(x, y) = sin(mπx/L) · sin(nπy/L)
```

Sand settles where `Z = 0` — the nodal lines. The pattern complexity grows with `m + n`. Frequency maps to mode via `f ∝ (m² + n²)`, so higher pitches produce denser, more intricate geometry.

For polyphonic input, modes are superimposed:

```
Z(x, y) = Σ aᵢ · sin(mᵢπx) · sin(nᵢπy)
```

where `aᵢ` is the normalized HPS magnitude of each detected fundamental.

## Pipeline

```
Microphone
    │
    ▼
getUserMedia() — echoCancellation, noiseSuppression, autoGainControl all OFF
    │
    ├──► YinProcessor (AudioWorklet)
    │       Ring buffer → 2048-sample window
    │       YIN algorithm (de Cheveigné & Kawahara, 2002)
    │       Parabolic interpolation for sub-sample freq accuracy
    │       postMessage → main thread → tuner UI
    │
    └──► HpsProcessor (AudioWorklet)
            Ring buffer → 4096-sample window, 50% overlap
            Hann window → FFT (Cooley-Tukey radix-2, in-place)
            Harmonic Product Spectrum (order 5)
            RMS silence gate + peak persistence (3 frames)
            Octave deduplication via semitone merging
            postMessage → main thread → chord UI + Chladni canvas
```

Both processors run on the **audio rendering thread**, not the main thread. The main thread only receives structured-clone messages with detected frequencies. Heavy canvas work (Chladni render) can't cause audio glitches.

Mic access requires a secure context (`http://localhost` or `https://`). Serving via `file://` will not work.

python3 -m http.server
# open http://localhost:8000/demo-poly.html

## Algorithms

### YIN (single-note)
Autocorrelation-based fundamental frequency estimator. Steps: difference function → cumulative mean normalization → absolute threshold → parabolic interpolation. Buffer size: 2048 samples (~46ms at 44.1kHz). Frequency range: 60–1400 Hz.

### HPS (polyphonic)
FFT magnitude spectrum is downsampled by integer factors 2–5 and multiplied element-wise. Peaks survive where harmonics consistently have energy — i.e. real musical fundamentals. Peak picking uses parabolic interpolation for sub-bin accuracy. Peaks require 3 consecutive frames of presence before being reported (~140ms at 50% overlap).

### Chladni renderer
Grain positions are generated by a seeded deterministic PRNG (mulberry32), keyed on the detected semitones. Same chord → same seed → same pattern. No flickering on stable input. Grain count: 12k (single note) / 18k (chord).
